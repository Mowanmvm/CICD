排查方法论

🔍 5-Why 分析法

连续追问 5 个"为什么"找到根因。例：服务挂了 → 为什么？OOM → 为什么？内存泄漏 → 为什么？某接口未关流 → 为什么？代码缺少 finally → 修复！

📊 USE 方法论

对每种资源检查：Utilization（使用率）、Saturation（饱和度）、Errors（错误数）。覆盖 CPU、内存、磁盘、网络。

🩺 RED 方法论

面向服务的监控：Rate（请求速率）、Errors（错误率）、Duration（延迟）。适合微服务。

📈 四个黄金信号

Google SRE 提出：延迟、流量、错误、饱和度。最经典监控框架。

🪪 分层排查法

物理层 → 网络层 → 系统层 → 中间件层 → 应用层。避免跳跃式排查。

🔄 变更关联法

70%的故障由变更引起。最近发布了什么？改了配置？依赖变化？从变更记录入手是最快的方式。

2. 日志实时监控与告警脚本 — 滚动监控日志并触发告警

#!/bin/bash
# 用途：实时监控应用程序日志，当出现 ERROR/FATAL 等关键字时触发告警
# 用法：./log_watcher.sh /var/log/app/app.log "ERROR|FATAL|Exception"

LOG_FILE="${1:-/var/log/syslog}"       # 第一个参数：日志文件路径，默认 /var/log/syslog
KEYWORD="${2:-ERROR|FATAL}"            # 第二个参数：匹配关键字，支持正则 OR
ALERT_URL="https://hooks.xxx.com/send" # 告警 webhook 地址（钉钉/飞书/企微机器人）

if [ ! -f "$LOG_FILE" ]; then          # -f 判断文件是否存在且为普通文件
    echo "错误：日志文件 $LOG_FILE 不存在！"
    exit 1                             # exit 非0表示脚本异常退出
fi

tail -F "$LOG_FILE" | while read line; do     # tail -F 跟踪文件（含文件轮转），逐行读取
    if echo "$line" | grep -qE "$KEYWORD"; then  # grep -q 静默模式（不输出），-E 扩展正则
        echo "[$(date '+%Y-%m-%d %H:%M:%S')] 发现匹配: $line" | tee -a /var/log/alert.log
        # date 格式化时间戳，tee -a 同时输出到屏幕和追加到文件

        curl -s --connect-timeout 5 -X POST -H "Content-Type: application/json" \
            -d "{\"msg\": \"【告警】$HOSTNAME 日志匹配: $KEYWORD\n$line\"}" "$ALERT_URL" \
            || echo "发送告警失败"  # || 表示上条命令失败时执行
    fi
done

3. 磁盘空间自动清理脚本 — 防止磁盘写满导致服务宕机

#!/bin/bash
# 用途：检查磁盘使用率，超过阈值则自动清理指定目录的老文件，并发送告警
# 用法：配合 crontab 定时执行：0 */6 * * * /opt/scripts/disk_clean.sh

THRESHOLD=85                 # 磁盘使用率告警阈值（百分比）
CLEAN_DIRS=("/var/log" "/tmp")  # 需要清理的目录列表（用空格分隔）
RETENTION_DAYS=7             # 保留天数，超过此天数的文件将被删除
ALERT_EMAIL="admin@example.com"

USAGE=$(df / | awk 'NR==2 {print $5}' | sed 's/%//')
# df 获取根分区使用率，awk 'NR==2 {print $5}' 取第二行第五列（Use%），sed 去掉百分号

echo "[$(date)] 当前根分区使用率: ${USAGE}%"

if [ "$USAGE" -gt "$THRESHOLD" ]; then    # -gt 表示大于（great than）
    echo "磁盘使用率超过阈值 ${THRESHOLD}%，开始清理..."

    for DIR in "${CLEAN_DIRS[@]}"; do     # 遍历待清理目录列表
        if [ -d "$DIR" ]; then            # -d 判断是否为目录
            FILES_COUNT=$(find "$DIR" -type f -mtime +$RETENTION_DAYS 2>/dev/null | wc -l)
            # find -mtime +N N天前修改过的文件，wc -l 统计数量

            if [ "$FILES_COUNT" -gt 0 ]; then
                find "$DIR" -type f -mtime +$RETENTION_DAYS -delete 2>/dev/null
                echo "已清理 $DIR 中 $RETENTION_DAYS 天前的文件 ${FILES_COUNT} 个"
            fi
        fi
    done

    NEW_USAGE=$(df / | awk 'NR==2 {print $5}' | sed 's/%//')
    echo "清理后使用率: ${NEW_USAGE}%"

    if [ "$NEW_USAGE" -gt "$THRESHOLD" ]; then
        echo "清理后仍超阈值，发送告警通知"
        mail -s "[警告] $(hostname) 磁盘使用率 ${NEW_USAGE}%" "$ALERT_EMAIL" <<< \
            "服务器 $(hostname) 磁盘使用率达 ${NEW_USAGE}%，请及时处理！"
    fi
fi

#!/bin/bash
# 用途：通过 SSH 在批量服务器上执行命令，用于配置下发、状态采集、补丁更新等
# 前提：已配置 SSH 免密登录（ssh-copy-id）

HOSTS_FILE="hosts.txt"      # 主机列表文件，每行一个 IP 或主机名
SSH_USER="root"              # SSH 登录用户名
SSH_PORT=22                  # SSH 端口
TIMEOUT=10                   # SSH 连接超时秒数
LOG_DIR="./batch_logs"       # 日志输出目录

mkdir -p "$LOG_DIR"          # -p 递归创建目录，如果已存在也不报错
TIMESTAMP=$(date '+%Y%m%d_%H%M%S')  # 时间戳，用于日志文件名

if [ ! -f "$HOSTS_FILE" ]; then
    echo "错误：主机列表文件 $HOSTS_FILE 不存在！"
    echo "创建格式：每行一个 IP，如："
    echo -e "192.168.1.1\n192.168.1.2"
    exit 1
fi

echo "=== 批量执行开始: $(date) ==="
echo "目标主机: $(wc -l < "$HOSTS_FILE") 台"

while IFS= read -r host; do          # IFS= 防止行首尾空格被去掉，-r 防止反斜杠转义
    [ -z "$host" ] && continue       # -z 判断字符串为空则跳过空行
    [[ "$host" =~ ^# ]] && continue  # 跳过以 # 开头的注释行（=~ 正则匹配）

    echo -e "\n>>> 正在连接: $host"
    LOG_FILE="${LOG_DIR}/${host}_${TIMESTAMP}.log"

    ssh -o StrictHostKeyChecking=no -o ConnectTimeout=$TIMEOUT \
        -p "$SSH_PORT" "${SSH_USER}@${host}" "$@" > "$LOG_FILE" 2>&1

    if [ $? -eq 0 ]; then            # $? 上一条命令的退出码，0 表示成功
        echo "[成功] $host — 输出已保存到 $LOG_FILE"
    else
        echo "[失败] $host — 请检查网络或认证配置"
    fi
done < "$HOSTS_FILE"                 # 将文件内容重定向给 while 循环作为输入

echo "=== 批量执行结束: $(date) ==="
echo "日志目录: $LOG_DIR"

5. MySQL 数据库自动备份脚本 — 全量备份与清理

#!/bin/bash
# 用途：自动备份 MySQL 数据库，保留最近7天备份，支持压缩和远程同步
# 用法：配合 crontab：0 3 * * * /opt/scripts/mysql_backup.sh

DB_USER="backup"             # 数据库备份用户（建议创建专用用户，最小权限）
DB_PASS="your_password"      # 密码（生产环境建议使用 my.cnf 配置文件，避免密码明文）
DB_HOST="localhost"
DB_PORT=3306
BACKUP_DIR="/data/backup/mysql"     # 备份文件存储目录
RETENTION_DAYS=7                     # 保留最近 N 天的备份
REMOTE_BACKUP="admin@backup-server:/backup/mysql"  # 远程备份地址（可选）

mkdir -p "$BACKUP_DIR/$(date +%Y%m%d)"  # 按日期创建子目录

# 获取所有数据库列表，排除系统库
DATABASES=$(mysql -u"$DB_USER" -p"$DB_PASS" -h"$DB_HOST" -P"$DB_PORT" \
    -e "SHOW DATABASES;" -N -B 2>/dev/null | grep -Ev "information_schema|performance_schema|mysql|sys")
# mysql -N 不显示列名，-B 批处理模式，grep -Ev 排除系统库

for DB in $DATABASES; do
    echo "正在备份数据库: $DB"
    BACKUP_FILE="${BACKUP_DIR}/$(date +%Y%m%d)/${DB}_$(date +%H%M%S).sql"

    # mysqldump --single-transaction InnoDB 热备不加锁
    # --routines 包含存储过程，--triggers 包含触发器
    mysqldump -u"$DB_USER" -p"$DB_PASS" -h"$DB_HOST" -P"$DB_PORT" \
        --single-transaction --routines --triggers --quick \
        "$DB" 2>/dev/null > "$BACKUP_FILE"

    gzip -f "$BACKUP_FILE"  # gzip 压缩备份文件（可压缩 5-10 倍）
    echo "  完成: ${BACKUP_FILE}.gz ($(du -h "${BACKUP_FILE}.gz" | cut -f1))"
done

find "$BACKUP_DIR" -type d -mtime +$RETENTION_DAYS -exec rm -rf {} \; 2>/dev/null
echo "已清理 ${RETENTION_DAYS} 天前的旧备份"

if [ -n "$REMOTE_BACKUP" ]; then            # -n 判断字符串非空
    rsync -avz --delete "$BACKUP_DIR/" "$REMOTE_BACKUP" --log-file=/var/log/backup_rsync.log
    # rsync -a 归档模式，-v 详细，-z 传输压缩，--delete 两端保持一致
fi
echo "备份全部完成: $(date '+%Y-%m-%d %H:%M:%S')"

#!/bin/bash
# 用途：批量检测目标主机的端口连通性、DNS 解析、HTTP 状态、路由追踪

TARGETS=(
    "baidu.com:80"
    "google.com:443"
    "192.168.1.1:22"
    "api.example.com:443"

echo "========== 网络诊断报告: $(date) =========="

    host=$(echo "$target" | cut -d: -f1)   # cut -d: -f1 按冒号分割取第一部分（主机）
    port=$(echo "$target" | cut -d: -f2)   # cut -d: -f2 取第二部分（端口）

    if timeout 5 nc -zv "$host" "$port" >/dev/null 2>&1; then
        echo "  [ ✓ ] $host:$port — 可达"
    else
        echo "  [ ✗ ] $host:$port — 不可达"
    fi
done

echo -e "\n>>> 模块2：DNS 解析测试"
for dns in "${DNS_SERVERS[@]}"; do
    RESULT=$(dig +short @"$dns" "www.baidu.com" 2>/dev/null | head -1)
    if [ -n "$RESULT" ]; then
        echo "  [ ✓ ] DNS $dns — 正常"
    else
        echo "  [ ✗ ] DNS $dns — 失败"
    fi
done

echo -e "\n>>> 模块3：HTTP 状态检查"
for url in "https://api.example.com/health" "https://status.example.com"; do
    HTTP_CODE=$(curl -o /dev/null -s -w "%{http_code}" --connect-timeout 5 --max-time 10 "$url")
    echo "  [ $HTTP_CODE ] $url"
done

echo -e "\n>>> 模块4：路由追踪"
GATEWAY=$(ip route | grep default | awk '{print $3}')
if [ -n "$GATEWAY" ]; then
    traceroute -m 15 -n "$GATEWAY" 2>/dev/null || echo "traceroute 未安装"
fi

echo -e "\n>>> 模块5：网卡错误统计"
for iface in $(ip -o link show | awk -F': ' '{print $2}'); do
    ERRORS=$(ip -s link show "$iface" | grep -A1 "errors" | tail -1 | awk '{print $2}')
    if [ "$ERRORS" != "0" ] && [ -n "$ERRORS" ]; then
        echo "  [ ⚠ ] $iface — 错误包数: $ERRORS"
    fi
done
echo -e "\n========== 诊断完成 =========="

Client → Server: SYN (seq=x)

Client → Server: FIN
Server → Client: ACK
Server → Client: FIN
Client → Server: ACK → TIME_WAIT (等 2MSL ≈ 60s)

场景 1：CPU 100% 排查

某 Java 应用 CPU 飙到 100%，你需要：

  1. 找到高 CPU 的进程 PID（top -c）
  2. 定位到具体线程（top -Hp PID）
  3. 分析线程堆栈找到问题代码（jstack/arthas）

提示：top -Hp, printf %x, jstack

场景 2：磁盘空间满

数据库写入报错 "No space left on device"：

  1. 确认分区使用情况（df -h）
  2. 找到最大目录（du -sh /*）
  3. 处理或清理文件（lsof | grep deleted 查未释放文件）

场景 3：服务频繁重启（OOMKilled）

K8s Pod 状态 OOMKilled，每隔一段时间重启：

  1. kubectl describe pod 查看 events
  2. 检查容器内存 limits 是否合理
  3. 排查内存泄漏（jmap/pprof）或调大 limits

场景 4：502 Bad Gateway

Nginx 反向代理报 502：

  1. 检查后端是否存活（ss/netstat）
  2. 查看 Nginx error log
  3. 检查上游连接超时和 keepalive 设置

场景 5：K8s Pod 起不来

新部署的应用 Pod 一直 CrashLoopBackOff：

  1. kubectl logs POD --previous 看上次日志
  2. kubectl describe pod 看 events
  3. 检查健康检查端点是否正确
  4. 进入容器手动启动排查

场景 6：MySQL 连接数暴涨

突然出现 "Too many connections"：

  1. SHOW PROCESSLIST 看连接来源
  2. 检查是否有大事务/Sleep 堆积
  3. 临时调大 max_connections 止血
  4. 排查应用连接池泄漏

⚡ 项目七：Redis 集群搭建（三主三从）

为什么需要 Redis 集群？

解决单机 Redis 的内存上限和单点故障问题。集群通过分片（16384 个 hash slot）将数据分散到多个节点。

# 用 Docker Compose 快速搭建 6 节点集群
# 需要 6 个 Redis 实例（3 主 + 3 从）

# 创建集群（在任一节点执行）
redis-cli --cluster create \
  10.0.1.1:6379 10.0.1.2:6379 10.0.1.3:6379 \
  10.0.1.4:6379 10.0.1.5:6379 10.0.1.6:6379 \
  --cluster-replicas 1

# 验证
redis-cli -c -h 10.0.1.1 -p 6379 cluster info
redis-cli -c -h 10.0.1.1 -p 6379 cluster nodes
注意：集群模式下不支持多 key 跨 slot 的操作（如 mget），需要设计好 key 的 hash tag（用 {} 指定 hash 范围，如 user:{123}:info 和 user:{123}:orders 会在同一个 slot）。
